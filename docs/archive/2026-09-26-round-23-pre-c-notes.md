## Примечания перед стартом раунда C («Кнопки и уведомления»)

Я сверил текущий код плагина (`class-settings.php`, `class-buttons.php`, `class-button-renderer.php`, `class-toasts.php`, `compare.js`) с исходной спецификацией v0.9. Перед тем как писать код раунда C, важно обратить внимание на **5 моментов**:

### 1. Варианты и место настройки «Повторный клик» (`second_click_action`)
- **Какие варианты:** в старой спецификации v0.9 (ответ 55) были зафиксированы ровно **два варианта**:
  - `remove` *(по умолчанию)* — убрать товар из сравнения;
  - `open_page` — перейти на страницу сравнения (`window.location.href = data.comparePage`).
  Третий вариант «ничего не делать» лучше не добавлять: для покупателя клик по активной кнопке без реакции выглядит как зависший скрипт.
- **Защита от пустого адреса:** если выбран `open_page`, но страница сравнения удалена или не назначена (`comparePage` пустой), скрипт безопасно откатывается к `remove`, чтобы не вести в пустоту.
- **Где разместить в админке:** раз все настройки поведения кнопки собраны во вкладке **«Кнопки и уведомления»**, предлагаю положить `second_click_action` прямо туда — рядом с текстами состояний «Сравнить» и «Уже в сравнении». *(Если хотите видеть её именно в «Основном» — скажите, положу туда).*

### 2. Что входит в блок «Где показывать» (пункт B1 из старого ТЗ)
Сейчас в коде есть выбор позиции (`after_cart` … `off`) и исключения товаров/категорий, но ещё нет фильтрации по контекстам и URL из старого ТЗ (ответ 57):
- **Контексты WooCommerce** (чекбоксы): магазин (`shop`), категории/таксономии (`catalog`), поиск (`search`), главная (`home`), похожие товары (`related`), апсейлы (`upsells`), корзина/кросс-сейлы (`cart` — **по умолчанию выключено**).
- **Страницы и URL с маской `*`**: переключатель режима («показывать везде, кроме указанных» / «показывать только на указанных») + текстовое поле масок по одной на строку с подсказкой про `*`.
- *Примечание:* шорткод `[rvn-compare-button]` с явным `id`, как и для товарных исключений, эти ограничения игнорирует.

### 3. Выбор иконки кнопки (пункт B4 из старого ТЗ)
Сейчас в `Button_Renderer::ICONS` зашиты 3 SVG-иконки (`compare` — столбцы, `compare_alt` — две карточки, `in_list` — галочка), без выбора в настройках. По старому ТЗ (ответ 33) в раунде C нужно добавить:
- выбор из **встроенного набора SVG** (весы, столбцы, две карточки — для кнопки сравнения; галочка — для состояния «в списке»);
- режим **свой emoji** (один символ/графема, очищается на сервере);
- режим **«без иконки»** (принудительно текстовый вид без SVG).
*(Произвольный SVG отложен до 1.3+ и только через PHP-фильтр — это мы уже зафиксировали).*

### 4. Шаблоны уведомлений и подстановки (пункт B6 из старого ТЗ)
Сейчас тексты уведомлений в `Toasts::labels()` берутся только из перевода и используют позиционные `%1$s` / `%1$d`. Чтобы администратор мог удобно менять шаблоны в админке:
- пустое поле в настройках по-прежнему означает **встроенный перевод** (чтобы смена языка сайта работала без ручной правки);
- в пользовательских шаблонах и в `compare.js` поддержим понятные подстановки из старого ТЗ: **`{product}`**, **`{category}`**, **`{count}`**, **`{limit}`** (при этом старые `%1$s`/`%1$d` во встроенных переводах продолжат работать).

### 5. Объём раунда C: лучше разделить на два шага (C1 и C2)
В отличие от раунда B (где менялась только админка, а логика уже была в PHP), в раунде C дорабатываются **и админка, и PHP/JS витрины** (повторный клик, контексты показа, иконки/emoji, шаблоны уведомлений с подстановками). Чтобы не упереться в лимит шагов и спокойно прогнать проверки, рекомендую пройти раунд C в два коротких шага:
- **Раунд C1 — Кнопки:** вкладка «Кнопки и уведомления» в React-аппе + позиции, режимы (компьютер/телефон), тексты, повторный клик (`remove` / `open_page`), выбор иконки/emoji, блок «Где показывать» (контексты + URL-маски) + уровень 0.
- **Раунд C2 — Уведомления и отступы:** позиции тостов (компьютер/телефон), длительность, настраиваемые шаблоны уведомлений с `{product}`/`{category}`/`{count}`/`{limit}`, отдельные отступы для телефона (`scroll_offset_top_mobile`, `scroll_offset_bottom_mobile`, пункт B7) + уровень 0 и **уровень 1 на стенде `main`** (с проверкой и админки, и витрины).

Все новые ключи настроек остаются внутри единой опции `rvn_compare_settings` (которая уже удаляется в `uninstall.php`), поэтому плодить отдельные записи в `wp_options` не придётся.
